================================================================
여주 프리미엄 아울렛 · 가로등 배너 관리 시스템
React + Vite + Supabase (PostgreSQL + Auth + RLS + Storage)
GitHub: https://github.com/kekeke9628/banner-admin
================================================================

【프로젝트 개요】
- 아울렛 내 100개 가로등 배너 자산을 지도 위 핀으로 시각화
- 공개 사용자: 빈 배너 조회 + 사용 신청 (회원가입 불필요)
- 관리자: 매직링크 로그인 → 예약 관리, 핀 위치 편집, 승인/반려, 이미지 등록
- Supabase RLS로 공개/관리자 데이터 분리
- GitHub Actions cron으로 매일 09:00 KST Slack 알림
- Supabase DB 트리거 + pg_net으로 신청 접수 시 Google Sheets 미러링

【스택】
- Frontend: React 18, Vite, CSS (no Tailwind)
- Backend: Supabase (PostgreSQL, Auth, Storage, Edge Functions)
- 배포: GitHub Pages (vite base: '/banner-admin/')
- 알림: Slack Incoming Webhook, Google Apps Script Webhook

-- 가로등 배너 자산
create table if not exists banners (
  id         text primary key,           -- 'L001' ~ 'L100'
  name       text not null,
  zone       text not null check (zone in ('WEST', 'EAST')),
  x          numeric(5,1) not null,      -- 지도 가로 위치 % (0–100)
  y          numeric(5,1) not null,      -- 지도 세로 위치 % (0–100)
  active     boolean not null default true,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

-- 확정 예약
create table if not exists bookings (
  id                    uuid primary key default gen_random_uuid(),
  banner_id             text not null references banners(id),
  type                  text not null check (type in ('tenant', 'external')),
  start_date            date not null,
  end_date              date not null,
  client                text not null,
  manager               text not null,
  contact               text not null,
  unit_price            integer not null,
  status                text not null default 'confirmed'
                          check (status in ('confirmed', 'cancelled')),
  created_by            uuid references auth.users(id),
  source_application_id uuid,
  created_at            timestamptz not null default now(),
  check (end_date >= start_date)
);

-- 배너 게시 이미지
create table if not exists images (
  id           uuid primary key default gen_random_uuid(),
  banner_id    text not null references banners(id),
  name         text not null,
  storage_path text,
  src_url      text,
  start_date   date not null,
  end_date     date not null,
  created_at   timestamptz not null default now(),
  check (end_date >= start_date)
);

-- 공개 신청 접수 (회원가입 불필요)
create table if not exists applications (
  id          uuid primary key default gen_random_uuid(),
  request_id  uuid not null,
  banner_id   text not null references banners(id),
  type        text not null check (type in ('tenant', 'external')),
  start_date  date not null,
  end_date    date not null,
  company     text not null,
  manager     text not null,
  contact     text not null,
  consent     boolean not null,
  consent_at  timestamptz not null,
  status      text not null default 'pending'
                check (status in ('pending', 'approved', 'rejected')),
  created_at  timestamptz not null default now(),
  check (end_date >= start_date)
);

-- 관리자 허용 목록
create table if not exists admins (
  user_id    uuid primary key references auth.users(id) on delete cascade,
  email      text not null,
  created_at timestamptz not null default now()
);

  from bookings

create or replace function is_admin()
returns boolean language sql security definer stable as $$
  select exists (select 1 from admins where user_id = auth.uid())
$$;

[파일 5] src/App.jsx (핵심 상태/흐름)
================================================================

핵심 상태:
- banners: 배너 자산 목록 (id, name, zone, x, y)
- bookings: 확정/대기 예약 목록
- bStatus: 배너별 오늘/기간 상태 (available/inuse/reserved/pending/avail/unavail/partial)
- selected: 상세 패널에서 단일 선택된 배너 ID
- checked: Set<id> — 다중 선택 체크박스
- selectMode: 다중선택 모드 on/off
- period: { from, to, active } — 기간 조회 모드
- isAdmin: Supabase admins 테이블 기반 판별

핵심 흐름:
1. 공개 모드 진입 → DateGate 팝업 (기간 선택 or 오늘 기준)
2. 핀 클릭 → setSelected → DetailPanel 슬라이드인 → 신청하기 버튼
3. 체크박스 체크 → checked Set 업데이트 → 지도 핀 다중 하이라이트
4. 일괄신청 → ApplyModal → submitPublicApplication → applications 테이블
5. 관리자: QueuePanel에서 승인/반려, 겹침 시 ApprovalConflictModal

[파일 6] src/components/MapCard.jsx (핵심 구조)
================================================================

성능 핵심:
- pan을 React state 대신 useRef + 직접 DOM 조작 (pointermove마다 re-render 없음)
- Pin 100개는 React.memo로 감싸 불필요한 re-render 방지
- 휠 줌 핸들러: useEffect + ref로 stale closure 방지

panToPin (하단 목록 클릭 시 지도 부드럽게 이동):
  const panToPin = (banner) => {
    const nx = frameWidth/2 - (banner.x/100) * frameWidth * zoom;
    const ny = frameHeight/2 - (banner.y/100) * frameHeight * zoom;
    stageRef.current.style.transition = 'transform .32s cubic-bezier(.25,.8,.25,1)';
    applyT(clampedX, clampedY, zoom);
  };
  useEffect(() => { if (selected) panToPin(banners.find(b => b.id === selected)); }, [selected]);

핀 선택 표시:
  <Pin selected={selected === b.id || checked.has(b.id)} ... />
  → selected=true이면 .sel 클래스 → 골든 글로우 + 1.3× 스케일

줌 레벨 1.5 이상에서 라벨 자동 표시:
  className={'pin' + (z >= 1.5 ? ' zoomed' : '')}
  .pin.zoomed .pin-label { opacity: 1; }
